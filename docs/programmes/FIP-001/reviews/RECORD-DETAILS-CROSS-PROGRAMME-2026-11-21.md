# FIP-001 — Record Details four-programme consistency review
**Date:** 2026-11-21  
**Disposition:** EVIDENCE-ONLY REVIEW — OPERATOR ACCEPTED WITH THREE AMENDMENTS (2026-11-21). Recommendations revised below; no UI implementation, citation contract change, FCIF or canonical mutation authorised by this review.

## Scope and evidence
Read canonical `main` after PR #272 (citation) and PR #274 (Mutation Log presentation), including `src/pages/FrontierRecord.jsx`, `src/pages/FrontierRecord.css`, `src/components/RecordCitation.jsx`, `src/data/recordReference.js`, `src/data/corpus.js` and the record modules for all 32 registered records. Representative detailed samples: **FR-QE-0001**, **FR-QE-0003** (QE); **FR-AI-0007**, **FR-AI-0008**, **FR-AI-0009** (AI); **FR-AM-0001**, **FR-AM-0005** (AM); **FR-BT-0004**, **FR-BT-0007** (BT). This is a *source and presentation-design review*, not an independent mobile, screen-reader or interactive browser acceptance test. No analytics demand or user-citation frequency was measured.

## Operator amendment A — Full canonical title inspection (2026-11-21)
All **32 of 32** `claim.shortLabel` titles in `src/data/records/FR-*.js` were inspected against their canonical claim statements. All name an identifiable technical or scientific *subject*: an entity, capability, system, material, phenomenon, proposition or application. **This is not the same as identifying a named claimant**: most title strings describe field-level propositions rather than attributed company-specific assertions. Illustrative counterexamples to the rule “all titles identify who made the claim” are `FR-QE-0003` (*Fault-Tolerant Logical Qubits — Error Rate Scaling with Code Distance*), `FR-AI-0007` (*Autonomous AI Scientific Discovery — Novel, Correct, Independent*), `FR-AM-0001` (*Cold Fusion — Room-Temperature Nuclear Fusion in Electrochemical Cells*), and `FR-BT-0004` (*Liquid Biopsy — Early Cancer Detection Before Conventional Diagnosis*). FR-QE-0001 itself explicitly names Google/Sycamore; `Claim Subject: Google Quantum AI (Sycamore processor)` duplicates this framing. **Disposition:** remove its visible Claim Subject row, retain stored value, do not modify titles, and do not institute a rule that every record must name a particular claimant. Where a specific attribution problem arises, it belongs in a separate canonical evidence/claim review, not in this presentation correction.

## Duplicate-date proposal
- **Retain:** the status line's assessed date (quick first-screen orientation), the panel's Last Assessment date (administrative comparison with Last updated), the assessment-history dates (chronological purpose), and the State Warrant's latest assessment date (self-contained audit section).
- **Candidate for removal:** the `Assessed YYYY-MM-DD` mini-label within `Where the record stands`, which immediately repeats the status-line date on the same screen and does not add provenance. Check on records with reconstruction-date overlays and multiple assessments before making this change.
- Do not remove dates wholesale or conflate historical assessment date, record update date, State-entry date and reconstruction date.

## Proposed implementation gate and acceptance checks
One small **separate** shared-component PR, not an amendment to the already merged PR #272:
1. Following the full 32-title audit, remove the one-off conditional Claim Subject and Claim Class display rows and the separate Effective Reconstruction panel row. Leave all underlying `src/data/records/*` fields and titles untouched.
2. Keep shared `getRecordReference` output and existing citation formats intact.
3. Use a plain `Record details` label. Hide `record.status === "open"`; for `closed` show `Record status: Closed` with only a compact administrative-not-evidence qualifier. Any future unexpected status must not be silently suppressed. Keep the reconstruction's *single concise header marker* on FR-QE-0001 with the effective reconstruction date, and keep its existing detailed State Warrant provenance.
4. Add `Cite this record` action that actually expands the existing disclosure and makes it keyboard discoverable, accessible and focused; do not create a second citation UI.
5. Remove only the duplicate `Assessed YYYY-MM-DD` label from `Where the record stands`, after checking QE/AI/AM/BT date-overlay behavior, while preserving assessment dates in the header, panel, history and Warrant.
6. Validate on **FR-QE-0001** (legacy metadata + same-day contextual date), **FR-QE-0003** (historic date overlay), **FR-AI-0008** (stage review pending but `status=open`), **FR-AM-0001** and **FR-AM-0005** (closed but scientifically assessed), **FR-BT-0004** (multiple same-day assessments), and **FR-BT-0007** (recent admission). Check desktop, <=700px, keyboard disclosure, source-derived metadata, no corpus changes and all CI/tests.
7. Gate merge and production deployment separately, with Cloudflare Pages and canonical-main verification. Distinct Workers build failures should be classified with logs; a Pages pass is not proof that an unrelated Workers integration is healthy.

**Accepted review conclusion (with amendments):** On ordinary Open records the panel should show two principal data rows—Last Assessment and Last updated—plus change-log and Evidence Trajectories/citation links. Closed records additionally show a qualified administrative status. Remove the one-off Claim Subject and Claim Class display rows **for distinct reasons**; place the concise, dated S4 reconstruction qualifier only in the existing record header, with detailed provenance continuing in State Warrant. Preserve distinct date clocks and the existing citation contract. No taxonomy or new analytical layer is authorised. **Implementation still requires its own bounded PR; no website or canonical mutations in this review.**
