## Accompanying artifact check

Read the [author repository](https://github.com/Quantum-Rings/quantum-rings-rcs-gpu-cpu/tree/4ed53dbfb92f4168bec05d01607a1ad34e0d16f8) at `4ed53dbfb92f4168bec05d01607a1ad34e0d16f8` (commit timestamp 2025-04-29). Inspected its complete file tree, README, both `shared.py` circuit selectors, preparation/measurement scripts and both postprocessors. The code timestamp does not establish the paper's first-public date or accepted venue.

The selectors explicitly separate the 14-cycle fidelity and 20-cycle performance circuits. Measurement scripts request amplitudes from QuantumRingsLib. Both postprocessors calculate probabilities from those logged simulator amplitudes and feed them into `f_xeb`; neither visibly imports an independent Google-reference probability file. Consequently this artifact read does not verify the paper's claimed independent-reference fidelity comparison. It does not prove that the SDK's amplitudes are wrong or exclude an unpublished validation step.

README reproduction requires a licence/account and an experimental `quantumringslib-0.11.11` wheel requested from the supplier. The pinned tree contains orchestration code and QASM inputs but no published run logs, sample outputs or independent reference comparison. The workflow was inspected, not executed: the required wheel, licence and A100/SLURM cluster were not available in this review. Public orchestration scripts do not expose enough simulator internals to infer approximation/error guarantees.
